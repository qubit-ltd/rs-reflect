# rs-reflect v3 下游集成与文档修复设计

## 背景与事实基线

本设计依据 2026-10-13 对当前 Paseo workspace 的只读评审。目标运行时仓库为 `/data/working/qubit/rust-common/rs-reflect`，基线提交 `0cdd68c9ef3bf469e0d2a6d99a88c5b30d717b82`。当前公开过程宏是 `#[Reflect]`、`#[ReflectImpl]` 和 `bind_method!`；根模块不再导出应用级 `ReflectedRef`、`ReflectedMut`、`ReflectedOwned` 或 `reflect_impl`。

同级 `rs-model-metadata` 当前提交为 `5fbffd8fcc22899a4c336f850344f049409a2d09`，仍在 `src/__private.rs` 等处引用上述旧入口。对这一当前检出执行 `cargo check -p qubit-model-metadata --lib --offline` 得到 16 个编译错误。`rs-platform` 当前提交 `716a5157f043ce5b8d57ad491758a62b9b6ca7aa` 已包含 v3 迁移，但依赖模型元数据，须在上游接通后重新验证。

`rs-model-metadata` 的 `codex/rs-model-metadata-api-v3-rebuild` 与 `codex/rs-reflect-api-v3-t10` 分支含候选迁移改动；后者当时的工作树中 `rs-reflect` 相邻符号链接指向失效的 `/tmp` 路径。因此候选代码只能作为逐项比对的来源，不能把历史验收记录或该工作树视为当前检出已通过验证。

文档方面，`derive/README.zh_CN.md` 使用已删除的 `#[derive(Reflect)]`，对应 Markdown 示例检查报 `expected derive macro, found attribute macro Reflect`；其正文还称提供 `reflect`、`reflect_impl`。`src/descriptor/impl_descriptor/impl_definition_descriptor.rs` 的 Rustdoc 仍把 `#[reflect_impl]` 作为用户入口。旧实施计划 `doc/2026-10-13-breaking-api-refactor-plan.md` 的验收记录描述实施分支成果，但未明确当前下游分支仍不兼容。

## 目标与验收边界

1. 当前同级仓库的 `rs-reflect` → `rs-model-metadata` → `rs-platform` 源码依赖链可用；模型元数据的库、宏、集成测试与平台直接消费者按现行 v3 API 编译并通过其既有测试。
2. 中英文过程宏 README 的入口、示例和能力边界与实际导出一致；全部纳入 `scripts/check_markdown_examples.py` 的 Rust 代码块可编译并按声明运行。
3. 面向用户的 Rustdoc、README、指南和迁移说明不再推荐已删除的公开宏或应用级 `Reflected*` API；内部函数名 `reflect_impl`、生成代码标识符和历史引用不因同形而机械改名。
4. 旧计划保留历史记录，并明确区分“实施分支曾通过”与“当前同级检出已通过”；本轮验收证据记录具体提交、命令和退出码。

不以此任务新增反射能力、改动运行时公开 API、重写整套中英文指南，或迁移无关仓库。用户允许破坏性变更；本方案按 v3 契约直接迁移消费者，不恢复旧兼容入口。

## 方案选择

| 方案 | 影响 | 判断 |
| --- | --- | --- |
| 在 `rs-reflect` 恢复旧宏和 `Reflected*` 根导出 | 使两套入口长期共存，破坏已完成的 v3 边界，后续文档与维护成本增加 | 不采用 |
| 把候选迁移分支整体合并到当前下游 | 可能引入与当前下游后续提交冲突的无关改动；候选工作树的依赖路径也已失效 | 不直接采用 |
| 以 v3 为唯一契约，比对候选分支并选择性迁移当前下游，同时修正文档 | 改动集中，可逐层验证且保留当前下游后续修改 | **采用** |

## 设计细节

### 1. 下游 API 边界

`rs-reflect` 保持现有根导出与 `__private::codegen_v3` 协议。`rs-model-metadata` 将其隐藏的生成代码门面和生产 API 改为当前动态值与普通引用/值入口：类型及 impl 声明分别使用 `#[Reflect]`、`#[ReflectImpl]`，按当前 `FieldDescriptor`、构造及调用接口传递对象，必要时使用 `qubit_reflect::value` 或生成代码专用的 `__private::codegen_v3::value` 类型。具体改动须从编译错误与调用契约出发，保持模型层的错误恢复和私有字段访问策略；不得用宽松类型擦除掩盖不匹配。

先比较当前 `rs-model-metadata`、上述两个候选分支与当前 `rs-reflect` 的公开签名，列出每处旧入口及对应新入口。随后按 `src/__private.rs`、`src/property.rs`、`src/property_access_path.rs`、`src/resolve/graph.rs`、`derive/src/expand/model_impl.rs` 及实际搜索结果逐组迁移。候选分支中与当前下游较新工作无关或契约不符的修改不带入。`rs-platform` 只修复经构建证明仍不兼容的直接调用点；当前已迁移部分不重复改写。

显式保留已知限制：泛型 `ModelImpl` getter/setter 的使用点绑定若仍不受支持，应继续给出编译期诊断，并由现有 UI 测试覆盖；本任务不以恢复旧 API 或虚构动态单态化消除该限制。

### 2. 文档契约

`derive/README.zh_CN.md` 的宏清单改为与英文版相同的事实：`Reflect`、`ReflectImpl`、`bind_method!`；入门示例使用 `#[Reflect]`，trait 和 impl 说明分别指向正确宏。两种语言可独立表述，代码入口、功能、限制和示例结果必须一致。保留现有源码检出与版本说明；不声称尚未验证的发布状态。

对公开 Rustdoc 和维护中的 README/用户指南做定向搜索。`ImplDefinitionDescriptor` 的示例描述改为 `#[ReflectImpl]`。只有描述旧公开用法的文字才更正；例如 `derive/src/macros.rs` 的内部函数名、历史设计计划的旧状态说明及真实存在的 `invoke_local` 方法不属于错误命名。若搜索发现其他用户可见的过时宏诊断或示例，逐项与当前 parser/公开 API 核对后纳入同一修复。

Markdown 示例编译器已覆盖两种过程宏 README，无须新增重复的示例测试框架。保留该检查作为回归门禁；文档契约检查只负责结构化事实和链接，不能替代 Rust 编译。Rustdoc 文字搜索与 `cargo test --doc`、`cargo doc` 配合验证。

### 3. 验收记录的语义

在旧实施计划的验收记录末尾追加标注日期的“当前检出状态”说明，不改写原历史结论。记录三仓库的实际 HEAD、验证命令及退出码；只有当前同级检出全部通过后，才使用“当前集成完成”措辞。若某个验证因环境或私有依赖不可执行，记录具体阻碍，不引用旧分支的通过记录替代。

## 风险与处理

- **候选分支差异较大：** 以调用点和编译错误为单位迁移，并在每组完成后运行对应包的聚焦检查；不得覆盖当前下游较新的独立修复。
- **多仓库 Cargo 路径与缓存：** 验证时使用真实相邻目录，先确认每个路径存在；不要复用失效的 `/tmp` 符号链接。并发执行重型 Cargo 命令时分配独立 `CARGO_TARGET_DIR`，或串行运行。
- **文档检查并非完整语义检查：** 编译后的 README 示例还需人工核对文字中的宏名、错误边界和双语一致性。
- **集成范围可能扩大：** 如果平台检查暴露新的真实不兼容，只处理 v3 迁移所必需的调用点，并把新增范围与验证结果写入验收记录。

## 验收标准

在实际实现后，至少获得以下新鲜证据：`rs-reflect` 的相关单测、doctest、Markdown 示例与文档契约检查通过；当前 `rs-model-metadata` 的 `cargo check`、库与 derive 测试通过；当前 `rs-platform` 的 workspace check 及 core/model-runtime/testkit 相关测试通过；定向搜索无面向用户的旧公开宏用法；三仓库状态与证据被准确记录。完整 CI、Clippy、覆盖率和 fuzz 仅在最终集成阶段按仓库现有门禁运行，不把旧报告当作本轮结果。
