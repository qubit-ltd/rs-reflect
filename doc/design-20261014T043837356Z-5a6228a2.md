# rs-reflect CI 自测与重构验收记录修复设计

## 背景与依据

2026-10-14 的只读评审确认两项问题：

1. `scripts/tests/check_markdown_examples_tests.py::ParserTests::test_real_inventory_examples_are_isolated` 的内嵌 Rust 程序仍使用已移除的 `#[derive(Reflect)]` 和 `#[reflect(rename = "IsolatedExample")]`。当前入口是 `#[Reflect]`（见 `derive/src/lib.rs`）。运行 `python3 -m unittest discover -s scripts/tests -p '*tests.py'` 时，121 项中有 1 项因该程序编译失败；`.infra/ci/ci.toml` 将 `scripts/project-ci-check.sh` 接入 CI，而该脚本会运行这组测试。
2. `doc/2026-10-13-breaking-api-refactor-plan.md` 的“当前同级检出状态”仍有四条“待 T5 回填”。前面的历史验收记录和当前检出状态分属不同时间，未完成的附录使读者无法从该文档判断本轮实际验证了什么。

评审同时验证：`cargo test --workspace --all-features --locked`、按 `.infra/style/rustfmt.toml` 执行的格式检查、`scripts/check_document_contracts.py`、`rs-model-metadata` 与 `rs-platform-core` 的库级 `cargo check` 通过。这些证据不替代修复后的新鲜验证，也不代表两个下游的完整测试通过。工作树原有两份旧设计文档处于删除状态，修复不触碰它们。

## 目标与边界

- 恢复 Markdown 示例隔离测试：两个相同示例仍分别编译、运行，返回计数仍为 2。
- 使项目 CI 钩子不再因旧宏语法失败，同时保留真实 Rust 编译验证；不能把示例改成 `no_run`、跳过测试或只检查文本。
- 将旧重构计划的四条待填项变为有日期、提交标识、命令、退出状态与验证范围的当前状态记录。未执行或失败的检查应如实标记，不沿用历史通过结果。
- 仅修改上述测试夹具和旧计划的验收附录；无需改变运行时、宏、公开 API、双语 README 或双语用户指南。允许破坏性变更的授权在此不需要使用。

## 方案选择

### CI 自测

采用更新测试内嵌示例的最小方案：以 `#[Reflect]` 标注 `Example`，通过 `TypeDescriptor::of::<Example>()` 取得描述符，再用 `ReflectRegistry::initialize()?.get(descriptor.type_id())` 证明声明进入该独立示例程序的注册表。保留原测试把相同 Rust 代码放入两个 Markdown 块、`check_examples(root, [document]) == 2` 的行为，以继续覆盖多示例隔离。

未选择给已移除的 derive 宏增加兼容层，因为它会扩大公开 API、掩盖迁移遗漏；未选择把测试换成空 `main`，因为那会失去真实 inventory 注册校验。`Reflect` 宏与 `TypeDescriptor` 的导入和调用形式应以当前 `examples/field_patch.rs`、`doc/user_guide.md` 中可编译用法为准。

### 验收记录

保留旧计划中明确标为历史的 2026-10-13 结果；只更新末尾“当前同级检出状态”附录，标题注明新的核验日期。记录三处检出的实际 Git 提交、检查命令及退出码，并区分核心全量测试、项目 CI、下游库级检查与未覆盖的下游完整测试。四个“待 T5 回填”条目须全部移除。若某项未运行或未通过，写明实际状态和原因，不能为了使文档看起来完整而写成通过。若实施时目标检出已变化，以执行时的新鲜结果为准。

不重写整份历史计划，不新建中英文设计文档副本；该计划是历史实施记录，而本设计文件说明本次修复。当前 README 和用户指南的检查已通过，未发现与这两项问题直接相关的文本需要同步修改。

## 验证与验收

1. 在更改测试前运行单项测试，确认失败确实来自旧宏语法。更改后运行同一测试，预期两个隔离程序均成功，返回计数为 2。
2. 运行 `python3 -m unittest discover -s scripts/tests -p '*tests.py'`，预期全部通过；运行 `scripts/project-ci-check.sh`，预期退出码 0。若完整 `.infra/bin/ci-check.sh` 因环境或其他问题未通过，应如实记录，不宣称 CI 全绿。
3. 对当前目标检出运行 `cargo test --workspace --all-features --locked`，并对两个直接下游分别运行 `cargo check -p qubit-model-metadata --lib --locked`、`cargo check -p qubit-platform-core --lib --locked`。这些命令共享 Cargo 缓存时可串行执行。
4. 检查旧计划附录：无“待 T5 回填”、无把历史结果误称为当前结果；每条状态均能对应本次命令记录。检查最终差异仅涉及测试夹具和旧计划附录，且保留原有删除状态。

不要求在本轮文档产出时执行上述修复；这些是下一位执行者的验收条件。
